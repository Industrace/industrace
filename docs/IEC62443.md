# ISA/IEC 62443 — scope and limits

This guide describes what the **ISA/IEC 62443** module in Industrace 2.x covers, what it does **not** cover, and how to interpret compliance outputs. For enabling or disabling the module, see [CONFIGURATION.md](CONFIGURATION.md). For permissions, see [ADMINISTRATION.md](ADMINISTRATION.md#role-based-access-control-rbac).

---

## At a glance

| Topic | Industrace |
|-------|------------|
| **Purpose** | Assessment support for industrial security zones and requirements |
| **Standard part** | [IEC 62443-3-3:2013](https://www.isa.org/standards-and-publications/isa-standards/isa-iec-62443-series-of-standards) (system security requirements) |
| **Certification** | **No** — scores and statuses are for internal assessment only |
| **Availability** | Optional per tenant (off by default on new installs) |
| **Version** | Introduced in v2.0; enhanced in v2.1 (RE-level assessment, audit export) |

> **Disclaimer:** Industrace supports IEC 62443-3-3 **assessment** (zones, conduits, assets). Zone compliance status is derived from **SL-A vs SL-T**; Foundation Requirement (FR) percentages reflect **assessment scoring**, not a formal certification or attestation of conformity.

---

## Enabling the module

The module is controlled by `tenant.settings.features.iec62443` (boolean).

| Where | Default |
|-------|---------|
| Setup wizard | Off for new installations |
| Setup → Optional modules | Can be toggled later by an admin |
| Tenants without the key | **Enabled** (backward compatibility) |

When **disabled**:

- UI menus are hidden (Security Zones, Conduits, Compliance dashboard, IEC 62443 asset tab).
- Related API routes return `403` with `FEATURE_DISABLED`.
- Core CMDB, assets, and risk scoring continue to work; zone-based IEC 62443 risk factors are skipped.

## Scope — what Industrace provides

### Security architecture model

Industrace models the IEC 62443 zone-and-conduit concept:

- **Security Zones** — logical groupings of assets with a target Security Level (SL-T).
- **Asset–zone membership** — assets can belong to one or more zones with roles (primary, supporting, boundary, shared, monitoring, maintenance, safety) and optional interface scope.
- **Conduits** — controlled communication paths between zones (type, direction, encryption, authentication, flow justification).

Screenshots: [zones](images/IEC62443-zones.png), [conduits](images/IEC62443-conduits.png).

### Requirement catalog

On system setup, Industrace seeds the **IEC 62443-3-3:2013** catalog:

| Element | Count | Notes |
|---------|-------|-------|
| Foundation Requirements (FR) | 7 | FR 1–7 (IAC, UC, SI, DC, RDF, TRE, RA) |
| Security Requirements (SR) | 52 | Full SR set from 62443-3-3:2013 |
| Requirement Enhancements (RE) | 4 per SR | RE 1–4 for SL-based assessment |

Each SR records which entity types it applies to (zone, conduit, asset) and its valid Security Level range (SL 1–4).

Screenshot: [requirements](images/IEC62443-requirements.png).

### Assessments and evidence

For each zone (and applicable asset-level SRs):

- **SR assessments** — record compliance status per Security Requirement or per RE level.
- **Assessment statuses** — `compliant`, `non_compliant`, `partial`, `not_applicable`, `not_assessed`, `insufficient_info`.
- **Justification** — required for certain statuses.
- **Evidence** — notes and linked evidence records attached to assessments.

Zone assessments use `POST /compliance/zone/{id}/sr/{sr_id}/assessment`.

### Security Levels

Industrace calculates and displays three Security Level concepts:

| Level | Meaning | How it is derived |
|-------|---------|-------------------|
| **SL-T** | Security Level Target | Set by the user on the zone, conduit, or asset |
| **SL-A** | Security Level Achieved | Highest SL (1…SL-T) where all in-scope SRs/REs are compliant |
| **SL-C** | Security Level Capability | Based on security capabilities available on assets in the zone |

**Zone compliance status** (`compliant`, `partial`, `non_compliant`, `not_assessed`) compares SL-A to SL-T — this is the normative-style status shown on zone cards.

**FR percentages** and **assessment progress** are separate metrics:

- *Assessment progress* — share of in-scope SRs at SL-T that have at least one assessment recorded.
- *FR weighted score* — assessment scoring across Foundation Requirements; useful for tracking work, not for certification.

### Security capabilities

A catalog of practical security capabilities (authentication, encryption, logging, etc.) can be mapped to assets. Capability availability feeds **SL-C** estimation for zones.

Screenshot: [device capabilities](images/IEC62443-devicecapabilities.png).

### Compliance dashboard and audit export

- **Compliance page** (`/compliance`) — overview of zones, FR summaries, and compliance distribution.
- **Zone detail → Compliance tab** — per-zone SR/RE review and gap analysis.
- **Asset detail → IEC 62443 tab** — zone memberships and asset-level SR assessments.
- **Audit export** — CSV or JSON matrix (zone × SR × RE × status) for internal reviews.

### Risk scoring integration

When the module is enabled, IEC 62443 gaps contribute to the asset **vulnerability & exposure** dimension of risk scoring:

- SL-T vs SL-A gap penalty.
- Non-compliant or partially compliant status penalties.

See [risk-scoring.md](risk-scoring.md) for the full formula. When the module is disabled, these factors are skipped.

## Limits — what Industrace does **not** do

### Not a certification tool

Industrace is an **assessment and documentation aid**. It does **not**:

- Issue certificates or formal attestations of conformity.
- Replace a qualified assessor, auditor, or certification body.
- Guarantee that an IACS meets IEC 62443 in a legal or contractual sense.

All outputs should be treated as **internal working data** subject to your own review process.

### Partial standard coverage

Industrace implements **IEC 62443-3-3** (system security requirements and security levels). It does **not** cover other parts of the 62443 series, including but not limited to:

| Part | Topic | Status in Industrace |
|------|-------|----------------------|
| 62443-2-1 | Security program / policies | Not implemented |
| 62443-2-4 | Service provider requirements | Not implemented |
| 62443-4-1 | Secure product development lifecycle | Not implemented |
| 62443-4-2 | Technical security requirements for components | Not implemented (capabilities catalog is a simplified aid, not 4-2 certification) |

### Normative text and RE accuracy

- SR titles and descriptions are seeded from the standard structure.
- RE texts are **paraphrased** from IEC 62443-3-3 tables; where missing, placeholders refer you to the official standard for normative wording.
- For contractual or audit purposes, always cross-check against the **official IEC 62443-3-3:2013** publication.

### Manual, judgment-based assessments

- Compliance status depends on **human assessment** entered in the UI.
- Industrace does **not** automatically verify device configurations, network traffic, or control-system behaviour against SRs.
- Network Probes and vulnerability data may inform risk scoring but do **not** auto-assess SR compliance.

### SL-C is indicative

SL-C is derived from declared asset capabilities in the catalog. It is a **planning aid**, not a substitute for component-level SL certification (62443-4-2).

### Conduit SL-A

Conduit Security Level Achieved may use assessment data or a **preliminary estimate** when assessments are incomplete. Check the `sl_achieved_source` field (`assessment` | `preliminary` | `none`) in API responses.

### No automatic migration from v1

ISA/IEC 62443 data (zones, conduits, assessments, evidence) does **not** migrate automatically from Industrace 1.x. See [MIGRATION.md](MIGRATION.md).

| `security_zones` | Zone and membership CRUD |
| `evidence` | Compliance evidence records |
